# Code Review: GradDotProd GPT2

## Findings
- **Critical** `ghostEngines/supported_layers_grad_samplers_dotprod.py:155-173` with `ghostEngines/autograd_grad_sample_dotprod.py:149-188`: in mixed-precision runs (model fp32, train bf16) activations stay bfloat16 while backprops are float32. `_compute_linear_train_grad` feeds these mixed dtypes to `torch.einsum`, producing `RuntimeError: expected scalar type Float but found BFloat16`. Cast activations/backprops to a common dtype (ideally the parameter dtype) before train-grad einsums for Linear/Conv/Embedding paths.
- **Critical** `ghostEngines/supported_layers_grad_samplers_dotprod.py:181-211` plus positional embedding usage in `Examples/shared/gpt2.py:186-194`: positional embeddings are indexed with `pos` shaped `[T]`, so their backward `B` tensor is 2D. The embedding dot-product code assumes a batch dimension and sums over dims `[1,2]`, leading to `IndexError: Dimension out of range`. Either skip positional embeddings in the ghost hooks or provide per-sample position ids (`pos` repeated to `[batch, T]`) and guard against 2D inputs before computing dot products/train grads.
- **Major** `ghostEngines/autograd_grad_sample_dotprod.py:51-80` with `Examples/shared/gpt2.py:33-43`: the custom `LayerNorm` class is not `nn.LayerNorm`, so hooks are skipped and its parameters will lack `train_grad`. After the above fixes, `GradDotProdEngine.prepare_gradients()` will hit a missing-`train_grad` error for these layers. Add support for `shared.gpt2.LayerNorm` (dot-product + train-grad) or explicitly exclude these params from the engine.
